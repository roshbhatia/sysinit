## Context

Three layers reference Lima, and only one of them is going away.

The nested-guest layer is what this change removes: `inputs.nixos-lima`, the
`modules/nixos/lima/` overrides, the `nostromo` host, the `isLima` plumbing, and
the launchd agent in `modules/darwin/macos-tools.nix` that starts the VM at login.

The tool layer stays: `pkgs.lima` in `modules/darwin/macos-tools.nix`, for ad-hoc
VMs driven by hand.

The colima layer stays untouched: its package, its launchd agent, and the
`sysinit.darwin.colima.*` options that size it.

Two references are Lima-flavored but not Lima-specific. `modules/nixos/common/default.nix`
forces `$SHELL` to zsh because SSH-with-command yields a non-login shell; the
comment names Lima but the behavior is correct generally. `overlays/default.nix`
records why a lima package override was removed. Both stay; one comment is
reworded.

## Goals / Non-Goals

Goals:
- No nested-NixOS-VM machinery remains, and no dead conditional survives it.
- `lima` and colima keep working exactly as they do now.
- The flake has one input fewer.

Non-Goals:
- Removing `pkgs.lima` or anything colima.
- Touching `arrakis`.
- Refactoring `lib/builders.nix` beyond deleting the `isLima` branches.

## Decisions

### D1. Delete rather than gate off

The machinery goes, rather than staying behind a `false` default. A disabled
branch still has to evaluate, still has to be read, and still rots.

- Alternative rejected: set `lima = false` everywhere and leave the code. Rejected
  because that is the state the repository is already in, and it is what makes the
  code cost without paying: the branches are live in evaluation and dead in fact.

### D2. `isLima` disappears rather than becoming a stub

`lib/builders.nix` computes `isLima` from `hostConfig.lima`, and three modules
branch on it. All four go. A stub that always returns false would leave three
`lib.optional` calls whose condition no caller can ever satisfy.

- Alternative rejected: keep `isLima` as a permanently-false value for
  out-of-tree hosts. Rejected because this repository has no out-of-tree consumer,
  and `templates/discrete` is a copy that this change updates in the same pass.

### D3. Two phases, split by blast radius

The NixOS side cannot affect the running Mac, so it lands first and freely. The
darwin side removes a launchd agent, so it lands second, behind a build and an
owner-read generation diff.

- Alternative rejected: one commit for the whole removal. Rejected because it
  would put a launchd-agent removal in the same revert unit as a NixOS module
  deletion, so backing out the risky half would also back out the safe half.

### D4. The colima agent is the thing to verify, not the lima agent

Both agents are generated by the same `lib.optionalAttrs` region in
`macos-tools.nix`. The realistic failure is an over-wide edit that takes colima's
plist with it, which would silently break the docker backend rather than error.

- Alternative rejected: trust `nix flake check`. Rejected because no check asserts
  the colima agent exists; the option merely has a default. A generation diff is
  what actually sees it, which is why it is the owner gate.

## Rollout & Gating

1. Phase 1, NixOS side: delete the module tree, the host, the input, the
   `isLima` plumbing, and the yaml files. Gate: `nix flake check`, plus
   `nix flake show` proving `nostromo` is gone and `arrakis` remains.
2. Phase 2, darwin side: remove the launchd agent, the option, the SSH include,
   and the docs. Gate: `nix flake check`, then `nh darwin build`, then the owner
   reads the generation diff and confirms the colima agent is untouched, then
   push, then `nh darwin switch`.

The push precedes the switch because the live Mac builds from the pushed flake via
`sysinit.laurel`, not from the working tree. The kill switch is `git revert` of the
phase commit followed by a switch.

## Risks / Trade-offs

- An over-wide deletion in `macos-tools.nix` takes the colima launchd agent with
  it, breaking docker silently. Mitigation: the phase-2 owner gate is a generation
  diff read specifically for colima, and the proposal's Behavior criterion requires
  the colima plist to be byte-identical.
- Removing the flake input changes `flake.lock` for every other input's transitive
  graph if `nixos-lima` contributed a shared dependency. Mitigation: read the
  `flake.lock` diff and confirm only `nixos-lima` nodes leave.
- `templates/discrete` is a copy, so a partial edit leaves a template that
  references a deleted module. Mitigation: the Behavior grep covers the whole
  tracked tree, templates included.
- A grep-driven removal deletes a Lima-flavored line whose behavior is general.
  Mitigation: Non-goals names both such lines explicitly, so the sweep has a
  written allowlist rather than a judgment call per hit.

## Migration Plan

1. Phase 1 edits, then `nix flake check` and `nix flake show`.
2. Phase 2 edits, then `nix flake check`.
3. Verify: `nh darwin build`, which writes no system change.
4. Confirm: the owner reads the generation diff and decides whether the only
   launch-agent change is the `lima-*` removal.
5. Apply: push, then `nh darwin switch`.
6. Confirm after applying: `command -v limactl` still resolves and
   `launchctl list | grep colima` still shows the agent.

Rollback: `git revert` the phase commit, push, switch.

## Adversarial Review

The rubric is the proposal's `Behavior` criteria, the `Decisions` above, the
`Rollout & Gating` gates, and the proposal's `Non-goals`.

Two halves per the `adversarial-review` skill. `specutil check` is mandatory and
runs on every phase. The LLM critic loop is default-on and owner-gated; a waiver
is recorded as `Adversarial review: waived by owner`. When it runs, independent
critics attempt to break the phase with a concrete failing scenario naming a
violated rubric item, the author revises against surviving objections, and the
loop runs to a terminal state. The skill scales the round cap and stops early on
non-convergence or fix-induced churn. A cap hit is reported as open objections,
never as a pass.
